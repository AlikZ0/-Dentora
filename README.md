# Dentora

Локальное офлайн-приложение для ведения клиентов, выполненных работ, рентгеновских
снимков, фотографий и документов.

**Без backend.** Вся база живёт в браузере устройства (IndexedDB). Ничего не
уходит на серверы. Перенос данных между компьютером, iPhone и Android — через
один backup-файл, который вы создаёте сами.

```
                     DENTORA
                        │
           ┌────────────┴────────────┐
           │                         │
       IndexedDB                    PWA
           │                         │
           │                  Desktop + Mobile
      ┌────┴─────┐
      │          │
   Клиенты     Файлы
      │          │
   Работы     Рентгены / Фото / PDF
           ↕ EXPORT / IMPORT
          backup.zip
```

## Быстрый старт

Требуется Node.js 20+.

```bash
npm install       # установка зависимостей
npm run dev       # разработка: http://localhost:3000
```

### Production-сборка

```bash
npm run generate  # статическая сборка в .output/public
npm run serve     # локальный просмотр на http://127.0.0.1:4173
```

`.output/public` — это обычная папка со статикой. Её можно положить на любой
хостинг, во внутреннюю сеть клиники или отдать любым веб-сервером. Backend не
нужен ни на одном этапе.

> **Важно:** для работы Service Worker, камеры и постоянного хранилища сайт
> должен открываться по **HTTPS** или с **localhost**. По обычному `http://`
> на IP-адресе браузеры отключают часть возможностей.

### Полезные команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Dev-сервер с HMR |
| `npm run build` | Сборка (Nitro) |
| `npm run generate` | Статическая сборка PWA |
| `npm run preview` | Просмотр сборки через Nuxt |
| `npm run serve` | Просмотр `.output/public` обычным файловым сервером |
| `npm run typecheck` | Проверка типов (`vue-tsc`) |
| `npm test` | Модульные и интеграционные тесты (Vitest) |
| `npm run test:e2e` | Браузерные тесты (Playwright) |
| `npm run test:all` | Всё сразу: unit → сборка → браузер |

## Возможности

**Клиенты** — список, поиск (по имени, телефону, почте, заметкам), сортировка,
фильтр по дате прибытия, создание, редактирование, мягкое удаление с корзиной.

**Работы** — история выполненных работ у каждого клиента: дата, название,
описание, заметки. К работе можно прикрепить файлы.

**Визиты** — запись клиента на будущую дату и время, с напоминанием
(за 15 минут, час, день — настраивается). Расписание с группировкой
по дням, статусы визита, сводка на день.

**Файлы** — JPG, PNG, WEBP, HEIC, PDF, DICOM и другие форматы. Автоматическая
категоризация (рентген / фото / документ), превью, просмотрщик с zoom, pan,
поворотом и полноэкранным режимом. На телефоне — pinch-to-zoom и съёмка камерой.

**Backup** — экспорт всей базы в один ZIP-архив, импорт с предпросмотром,
два режима слияния, опциональное шифрование паролем, история экспортов и
ненавязчивое напоминание раз в день.

**Офлайн** — после первой загрузки приложение работает полностью без интернета.

## Архитектура

Строгое разделение слоёв. Компоненты не знают про IndexedDB, репозитории не
знают про Vue.

```
    UI (pages / components)
            ↓
    Composables (useToasts, usePanZoom, useConfirm, …)
            ↓
    Services (backup, encryption, files, storage)
            ↓
    Repositories (clients, works, files, meta)
            ↓
    Dexie → IndexedDB
```

**Стек:** Nuxt 3 (`ssr: false`) · Vue 3 Composition API · TypeScript strict ·
Pinia · Dexie 4 · `@vite-pwa/nuxt` (Workbox) · `fflate` · Web Crypto API.

Почему `fflate`, а не JSZip: `fflate` умеет потоковую запись и чтение архива,
поэтому backup на 1.4 ГБ не требует держать весь архив в памяти.

## Как работает IndexedDB

База называется `dentora`. Пять хранилищ:

| Хранилище | Что внутри | Индексы |
|---|---|---|
| `clients` | Клиенты | `id`, `lastName`, `firstName`, `arrivalDate`, `createdAt`, `updatedAt`, `deleted` |
| `works` | Выполненные работы | `id`, `clientId`, `date`, `[clientId+date]`, `updatedAt`, `deleted` |
| `appointments` | Запланированные визиты | `id`, `clientId`, `at`, `status`, `[status+at]`, `[clientId+at]`, `notifiedAt`, `deleted` |
| `files` | **Метаданные** файлов + маленькое превью | `id`, `clientId`, `workId`, `[clientId+createdAt]`, `kind`, `updatedAt`, `deleted` |
| `fileBlobs` | **Байты** файлов | `id` |
| `meta` | Настройки, история backup | `key` |

### Почему метаданные и байты лежат отдельно

Это ключевое решение всей архитектуры. Рентген легко весит 20–80 МБ. Если бы
байты лежали в той же записи, что и имя файла, то простое открытие карточки
клиента с 30 снимками означало бы десериализацию двух гигабайт.

Поэтому:

* `files` содержит только метаданные и превью до 320 px → список файлов
  открывается мгновенно;
* `fileBlobs` содержит оригинал → читается **только** когда пользователь
  открыл конкретный файл в просмотрщике;
* превью генерируется через `createImageBitmap` с уменьшением при декодировании,
  то есть полноразмерный bitmap в памяти не создаётся.

Файлы хранятся как `Blob`, а не как base64. Base64 увеличил бы объём на треть
и заставил бы держать содержимое в виде строки в памяти.

## Версии схемы и миграции

Текущая версия схемы: **3** (`src/database/schema.ts`).

При изменении структуры базы **нельзя** менять уже выпущенную версию — нужно
добавить новую запись в массив `versions` и, если требуется переписать данные,
функцию миграции в `src/database/migrations.ts`.

```ts
// schema.ts
export const DB_VERSION = 4

export const versions = [
  { version: 1, stores: { /* ...как было... */ } },   // не трогать
  { version: 2, stores: { files: '...' } },           // не трогать
  { version: 3, stores: { appointments: '...' } },    // не трогать
  { version: 4, stores: { works: '...новый индекс' } },
]
```

Dexie проигрывает всю цепочку версий по порядку, поэтому браузер, стоявший на
версии 1, корректно доедет до текущей. **База никогда не удаляется при
обновлении приложения**, данные пользователя сохраняются.

Реализованные миграции:

* **v1 → v2** — добавляет категорию файла (`kind`) и заполняет её для
  существующих записей по MIME-типу и имени файла;
* **v2 → v3** — добавляет хранилище визитов (`appointments`).

Тест `tests/migrations.test.ts` создаёт базу в формате v1, открывает её текущей
версией и проверяет, что не потерялась ни одна запись, а новые возможности
работают.

## Визиты и уведомления

### Как записать клиента

Из карточки клиента (**Визиты → + Визит**) или из раздела **Визиты**
(там нужно ещё выбрать клиента). Указываются дата, время, длительность,
название и за сколько напомнить.

Новый визит по умолчанию предлагает **завтра, 10:00** — самый частый случай.
Запись на прошедшее время разрешена (иногда нужно внести визит задним числом),
но приложение честно предупреждает, что напоминание уже не сработает.

### Что хранится

Время визита хранится как **локальное время без часового пояса** —
`2026-08-25T10:30`. Это сделано намеренно: приём, назначенный на 10:30,
остаётся приёмом на 10:30 независимо от того, в каком поясе находится
устройство. Если бы хранился момент в UTC, то перенос backup на телефон,
живущий в другом поясе, сдвинул бы все визиты. Побочная польза: такие строки
сортируются как обычный текст, поэтому индекс работает напрямую.

### Включение уведомлений

**Настройки → Уведомления о визитах**.

Переключатель делает две вещи сразу: включает настройку приложения и
запрашивает разрешение у браузера. Запрос обязан происходить прямо в момент
нажатия — если попросить позже, браузер молча откажет. Напоминания приходят,
только когда включено **и то, и другое**; если разрешение отозвано,
приложение прямо об этом пишет, а не делает вид, что всё работает.

Дополнительно настраивается:

* за сколько напоминать по умолчанию (от «в момент визита» до «за день»);
* сводка на день — одно уведомление при первом открытии приложения
  с количеством визитов на сегодня;
* кнопка «Проверить уведомление» — показывает, как оно выглядит.

### Честное ограничение

Приложение работает **без сервера**, а значит без Web Push. Отсюда следует:

* напоминание приходит, **пока приложение открыто или свёрнуто** —
  во вкладке, в фоне, в отдельном окне PWA;
* при **полностью закрытом** приложении браузер доставить уведомление
  не может, и приложение этого не обещает.

Поэтому напоминания — это подстраховка, а не единственный источник правды.
Основной способ увидеть расписание — раздел **Визиты** и блок «Ближайшие
визиты» на главной; они не зависят ни от каких разрешений.

### Как это устроено внутри

Не таймер на каждый визит, а опрос раз в 30 секунд, плюс проверка при
возвращении на вкладку и при получении фокуса. Причина: таймеры не переживают
засыпание вкладки или телефона, а проверка при пробуждении подхватывает всё,
что наступило за это время.

У каждого визита есть поле `notifiedAt`. Оно проставляется в момент показа,
поэтому напоминание приходит ровно один раз — даже после перезагрузки
страницы. Если платформа вообще не смогла показать уведомление, отметка
всё равно ставится: иначе цикл пытался бы снова каждые 30 секунд без конца.

Просроченные напоминания не «выстреливают пачкой»: если приложение не
открывали неделю, визиты недельной давности пропускаются (окно — 2 часа).

Перенос визита или смена времени напоминания **снимают** отметку, и
напоминание срабатывает заново для нового времени. Правка заметок — не снимает.

### Уведомления на iPhone

Работают начиная с **iOS 16.4** и **только для приложения, установленного на
экран «Домой»**. В обычной вкладке Safari уведомлений не будет вовсе.
Используется `ServiceWorkerRegistration.showNotification` — единственная форма,
которую поддерживает iOS; конструктор `new Notification()` там недоступен.

## Как работает backup

### Структура архива

```
backup/
  manifest.json
  database.json
  files/
    client-3f8a1b2c/
      xray-001-9d4e7a11.jpg
      photo-002-1c8b3f00.jpg
      document-a4f19b02.pdf
    client-77e0c419/
      xray-2026-08-1b9c4d07.jpg
```

`manifest.json` и `database.json` записываются **первыми**. Благодаря этому
предпросмотр импорта читает несколько сотен килобайт и останавливается — даже
если архив весит гигабайт.

### manifest.json

```json
{
  "format": "client-app-backup",
  "version": 1,
  "createdAt": "2026-08-23T23:59:12.000Z",
  "appVersion": "1.0.0",
  "databaseVersion": 2,
  "counts": { "clients": 247, "works": 381, "files": 624, "appointments": 42 },
  "totalFileSize": 1503238553
}
```

При импорте проверяются: `format`, `version` (не новее нашей), `databaseVersion`
(не новее нашей), корректность `createdAt`, целостность `database.json`,
безопасность путей внутри архива. Любая проблема даёт понятное сообщение,
а не техническую ошибку.

### Что происходит при экспорте

```
IndexedDB → manifest + database.json → ZIP (потоково) → [шифрование] → файл
```

JPEG/PNG/PDF кладутся в архив без сжатия (`STORE`) — они уже сжаты, и
дефлейт только грел бы процессор телефона. JSON сжимается.

### Куда сохраняется файл

Три пути, в порядке приоритета:

1. **File System Access API** (Chrome/Edge на десктопе) — потоковая запись
   прямо в выбранный файл, память не расходуется;
2. **Web Share API** (iPhone) — открывается системное меню «Поделиться»,
   откуда файл кладётся в «Файлы» / iCloud Drive / AirDrop;
3. **Обычная загрузка** (`<a download>`) — везде остальное.

## Merge и Replace

У каждой записи есть постоянный **UUID**, который сохраняется при экспорте и
импорте. Именно он позволяет узнать «ту же самую» запись, пришедшую с другого
устройства.

### Replace — заменить

Локальная база полностью очищается, вместо неё записывается содержимое backup.

* Требует подтверждения с показом «было / станет».
* Очистка выполняется **после** успешной проверки архива, поэтому повреждённый
  файл не может оставить вас с пустой базой.

Когда использовать: перенос базы на новое устройство, восстановление после сбоя.

### Merge — объединить

Записи из backup добавляются к текущим:

| Ситуация | Действие |
|---|---|
| UUID не встречается локально | добавить |
| UUID есть, `updatedAt` в backup новее | обновить |
| UUID есть, `updatedAt` такой же или старше | пропустить |

Дубликаты не создаются никогда. Повторный импорт одного и того же архива —
операция без эффекта. У файлов дополнительно сравнивается SHA-256: если
содержимое совпадает, байты не перезаписываются.

Когда использовать: вы работали и на компьютере, и на телефоне, и хотите
свести изменения вместе.

> Отметка о том, что напоминание уже показано (`notifiedAt`), при слиянии
> **не** перезаписывается: показали ли уведомление именно на этом устройстве —
> его собственное дело, и backup с другого телефона не должен заставить
> напоминание прозвучать второй раз.

> Разрешение конфликтов — «побеждает более свежая запись». Если один и тот же
> клиент правился на двух устройствах, сохранится правка, сделанная позже.

## Шифрование backup

Backup содержит персональные и медицинские данные, поэтому его можно защитить
паролем. Используется только стандартная криптография браузера (Web Crypto API),
ничего самодельного:

```
пароль → PBKDF2-SHA256 (600 000 итераций, случайная соль 16 байт)
       → ключ AES-256
       → AES-GCM
```

AES-GCM в Web Crypto нельзя применить потоково — он требует весь объём целиком.
Для архива на 1.4 ГБ это означало бы несколько гигабайт оперативной памяти.
Поэтому данные разбиваются на блоки по 4 МБ, каждый шифруется отдельно с
детерминированным IV (`nonce || счётчик`) и AAD, который привязывает номер блока
и признак последнего блока. Это стандартная конструкция STREAM: блоки нельзя
переставить, продублировать или обрезать незаметно.

Файл получает расширение `.zip.enc` и начинается с сигнатуры `DNTRAEN1`,
поэтому приложение само определяет, что нужен пароль.

**Пароль нигде не сохраняется** — ни в IndexedDB, ни в localStorage, ни в
памяти дольше самой операции. Забытый пароль означает безвозвратно потерянный
backup. При неверном пароле, повреждении или обрезке файла показывается одно и
то же сообщение: «Неверный пароль или повреждённый backup» — эти три случая
криптографически неразличимы.

## Перенос данных между устройствами

### С компьютера на другой компьютер

1. **Backup → Экспортировать данные** → сохраните `backup_….zip`.
2. Перенесите файл (флешка, облако, сеть).
3. На втором компьютере: **Backup → Импортировать backup** → выберите файл.
4. Проверьте предпросмотр (дата, количество клиентов, работ, файлов).
5. Нажмите **Заменить** (если база пустая) или **Объединить**.

### С компьютера на iPhone

1. На компьютере сделайте экспорт.
2. Положите `backup_….zip` в iCloud Drive, или отправьте через AirDrop,
   или сохраните в любое облако, доступное из приложения «Файлы».
3. На iPhone откройте Dentora (лучше — установленную на экран «Домой»).
4. **Backup → Импортировать backup**.
5. В открывшемся системном окне выберите **Обзор** → iCloud Drive / На iPhone /
   Загрузки и укажите файл.
6. Проверьте предпросмотр и выберите режим импорта.

### С iPhone на компьютер

1. На iPhone: **Backup → Экспортировать данные**.
2. Откроется системное меню «Поделиться». Выберите:
   * **«Сохранить в Файлы»** → iCloud Drive (потом заберёте с компьютера), или
   * **AirDrop** на Mac, или
   * отправку себе в мессенджер / почту.
3. На компьютере откройте Dentora → **Импортировать backup** → выберите файл.

> Если меню «Поделиться» не появилось (старая версия iOS), файл уйдёт в
> «Загрузки» Safari — оттуда его тоже видно в приложении «Файлы».

### С Android

Экспорт кладёт файл в «Загрузки». Импорт открывает системный выбор файлов, где
доступны «Загрузки», Google Drive и любые подключённые хранилища.

### Ежедневная привычка

Браузер **не может** сам сохранить файл на диск без действия пользователя — это
запрет безопасности, обойти его нельзя, и приложение этого не обещает. Вместо
этого:

* на главной видно, был ли сегодня backup;
* при первом за день открытии показывается ненавязчивый баннер
  «Сегодня ещё не создан backup»;
* в разделе Backup хранится история: последний экспорт, последний импорт,
  размер, общее число экспортов.

## Установка как приложение (PWA)

### iPhone / iPad

1. Откройте сайт **в Safari** (не в Chrome — на iOS установка доступна только из Safari).
2. Кнопка **«Поделиться»** внизу экрана.

Chrome → меню (⋮) → **«Установить приложение»**. Либо баннер установки, который

приложение».

### Windows / macOS / Linux

Chrome или Edge → значок установки в адресной строке → **«Установить»**.

## Где физически находятся данные

Данные лежат в хранилище IndexedDB того браузера и того профиля, где вы
работаете. Ни в какой сети их нет.

| Платформа | Путь |
|---|---|
| Windows (Chrome) | `%LOCALAPPDATA%\Google\Chrome\User Data\Default\IndexedDB\` |
| Windows (Edge) | `%LOCALAPPDATA%\Microsoft\Edge\User Data\Default\IndexedDB\` |
| macOS (Chrome) | `~/Library/Application Support/Google/Chrome/Default/IndexedDB/` |
| macOS (Safari) | `~/Library/Safari/Databases/` и `~/Library/WebKit/` |
| Linux (Chrome) | `~/.config/google-chrome/Default/IndexedDB/` |
| Linux (Firefox) | `~/.mozilla/firefox/<профиль>/storage/default/` |
| iOS | Внутреннее хранилище Safari/WebKit, недоступное из «Файлов» |
| Android | Внутреннее хранилище Chrome, недоступное файловому менеджеру |

Важные следствия:

* **Данные привязаны к браузеру и профилю.** Chrome и Firefox на одном
  компьютере — это две независимые базы.
* **Приватный режим / инкогнито** — данные исчезают при закрытии окна.
* **Очистка «данных сайтов»** в настройках браузера удалит базу. Backup — это
  единственная страховка.
* Скопировать папку IndexedDB вручную технически можно, но это не
  поддерживаемый способ переноса: формат внутренний и зависит от версии
  браузера. Используйте экспорт.

## Ограничения браузеров

**Объём хранилища.** Браузер выделяет долю от свободного места на диске
(Chrome — до ~60 %, Firefox — до 50 %, Safari — существенно меньше). Точную
цифру показывает **Настройки → Хранилище**. При приближении к лимиту
приложение предупреждает заранее, а перед сохранением большого файла
проверяет, хватит ли места, и выдаёт понятное сообщение вместо
`QuotaExceededError`.

**Вытеснение данных.** Если на устройстве заканчивается место, браузер может
удалить данные сайта. Защита — постоянное хранилище: приложение запрашивает его
автоматически, а вручную это можно сделать в **Настройки → Хранилище**.
Chrome обычно выдаёт его установленным PWA молча, Firefox спрашивает,
Safari игнорирует запрос.

**Одна вкладка на базу.** Если приложение открыто в нескольких вкладках и
происходит миграция схемы, остальные вкладки нужно закрыть — приложение об этом
скажет понятным текстом.

**Уведомления.** Требуют HTTPS (или localhost) и разрешения пользователя.
Firefox спрашивает при каждом запросе, Safari на macOS — тоже. Без сервера
уведомления приходят только при работающем приложении (см.
[Визиты и уведомления](#визиты-и-уведомления)).

**Форматы изображений.** HEIC декодируется только в Safari; в других браузерах
файл сохранится и экспортируется корректно, но превью не будет. DICOM
сохраняется как файл, но не отображается.

**PDF в просмотрщике.** Встроенный просмотр работает в десктопных браузерах.
На мобильных предлагается открыть файл системным приложением.

## Ограничения iOS

iOS — самая ограниченная платформа, и это учтено в коде.

**Удаление данных через 7 дней.** Safari удаляет хранилище сайтов, к которым не
обращались 7 дней. **На установленные на экран «Домой» приложения это
ограничение не распространяется.** Отсюда рекомендация: установите приложение и
делайте backup.

**Меньший объём хранилища.** Safari выделяет заметно меньше места, чем Chrome.
Следите за разделом Хранилище.

**Установка только из Safari.** Chrome и Firefox на iOS — это тот же WebKit,
но пункта «На экран «Домой»» у них нет.

**Нет `beforeinstallprompt`.** Кнопку «Установить» показать невозможно, поэтому
приложение показывает пошаговую инструкцию.

**Нет `requestFullscreen`.** Просмотрщик снимков и так занимает весь экран,
поэтому кнопка полноэкранного режима на iOS просто не показывается.

**Экспорт через «Поделиться».** Прямое сохранение в произвольную папку в iOS
Safari недоступно; используется Web Share API — это штатный и надёжный путь в
приложение «Файлы».

**Пустой `File.type`.** iOS иногда отдаёт файл без MIME-типа; тип определяется
по расширению.

**Уведомления только для установленного приложения.** iOS 16.4+ показывает
веб-уведомления исключительно для приложения, добавленного на экран «Домой».
В обычной вкладке Safari переключатель не сработает — приложение об этом
предупредит.

**Безопасные зоны.** Учтены `env(safe-area-inset-*)`: чёлка, Dynamic Island и
индикатор «Домой» не перекрывают интерфейс ни в портретной, ни в альбомной
ориентации.

**Зум при фокусе.** Все поля ввода имеют размер шрифта 16 px — иначе Safari
масштабирует страницу при касании поля.

## Безопасность и приватность

Что приложение **не делает**:

* не хранит данные в `localStorage` (только IndexedDB);
* не создаёт публичных ссылок на файлы;
* не отправляет данные ни на какие серверы;
* не подключает внешние аналитические SDK;
* не пишет ФИО, телефоны, почту, заметки и имена файлов в `console.log`.

Локальный диагностический журнал (`src/utils/logger.ts`) хранит только коды
операций и технические названия ошибок, живёт в памяти и никуда не отправляется.

Ошибки пользователю показываются человеческим языком. `QuotaExceededError`,
`DataCloneError`, `DOMException` на экран не попадают — вместо них, например:
«Не удалось сохранить файл. Возможно, на устройстве недостаточно свободного
места.»

Удаление защищено: клиент сначала попадает в корзину и может быть восстановлен;
«Удалить все данные» требует двух подтверждений, второе — с вводом слова
`УДАЛИТЬ`.

«Очистить кэш» удаляет **только** закэшированные файлы интерфейса и никогда не
трогает данные в IndexedDB.

### Ручная проверка в браузерах

Автотесты гоняются в Chromium. Перед выпуском стоит вручную пройти чек-лист в
остальных браузерах — особенно там, где движок другой:

| Браузер | Что критично проверить |
|---|---|
| Chrome / Edge (desktop) | File System Access при экспорте, установка PWA, большие файлы |
| Firefox (desktop) | Запрос постоянного хранилища, выбор файлов, IndexedDB |
| Safari (macOS) | IndexedDB, экспорт через загрузку, отображение WEBP-превью |
| **iPhone Safari** | Выбор фото из галереи, съёмка камерой, pinch-to-zoom, safe-area, отсутствие зума при фокусе полей |
| **iPhone PWA** | Установка на «Домой», офлайн-запуск, экспорт через «Поделиться», импорт из «Файлы» |
| **Android Chrome** | Установка, камера, «Загрузки» при экспорте и импорте |

Сценарий офлайн-проверки:

1. Открыть сайт, установить PWA.
2. Выключить интернет (авиарежим).
3. Создать клиента, добавить работу, приложить фотографию.
4. Закрыть приложение полностью.
5. Открыть снова — все данные на месте.

├── services/
│   ├── backup/                export, import, merge, validation, zip, paths
